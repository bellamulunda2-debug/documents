All Xera API endpoints that access user-specific data require authentication. When you sign in to Xera, the platform issues a short-lived **access token** (a JWT). Include that token in the `Authorization` header of every request to a protected endpoint. Unauthenticated requests return a `401 Unauthorized` response immediately.

## How Authentication Works

After a successful sign-in, Xera provides a session that contains an **access token**. Every subsequent API call must carry this token so the server can verify your identity and scope the response to your account. The token is tied to your Xera session — it grants access only to data belonging to that session.

```
Authorization: Bearer <your-access-token>
```

The server validates the token on each request. If the token is valid, the request proceeds. If the token is expired, missing, or malformed, the API returns `401`.

## Get Your Access Token

You can retrieve your access token in two ways — from browser DevTools (useful for testing) or programmatically via the Xera client session (recommended for integrations).

<Steps>
  <Step title="Sign in to Xera">
    Open [xera.app](https://xera.app) in your browser and sign in with your account credentials.
  </Step>
  <Step title="Open DevTools and find your session token">
    Open your browser's DevTools (`F12` or `Cmd+Option+I`), navigate to the **Application** tab, and look in **Local Storage** under `https://xera.app` for the entry that contains `auth-token`. The `access_token` field inside that entry is your bearer token.

    <Tip>
      If you don't find it in Local Storage, check the **Cookies** section of the same panel — the token may be stored there depending on your browser configuration.
    </Tip>
  </Step>
  <Step title="Or retrieve it programmatically from the session">
    If you're building an integration that runs in an authenticated context alongside the Xera app, retrieve the session programmatically:

    ```javascript
    const { data: { session } } = await xera.auth.getSession();
    const accessToken = session?.access_token;
    ```

    This approach always returns the current, non-expired token and is the recommended method for any code that runs on behalf of a logged-in user.
  </Step>
</Steps>

## Use the Token in Requests

Pass the token in the `Authorization` header with the `Bearer` scheme on every request to a protected endpoint.

<CodeGroup>
```javascript JavaScript (fetch)
const { data: { session } } = await xera.auth.getSession();

const response = await fetch('https://xera.app/api/app/discover/users', {
  headers: {
    'Authorization': `Bearer ${session.access_token}`,
    'Content-Type': 'application/json'
  }
});

const data = await response.json();
```

```bash cURL
curl -X GET https://xera.app/api/app/discover/users \
  -H 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
  -H 'Content-Type: application/json'
```

```python Python (requests)
import requests

headers = {
    'Authorization': 'Bearer YOUR_ACCESS_TOKEN',
    'Content-Type': 'application/json'
}

response = requests.get(
    'https://xera.app/api/app/discover/users',
    headers=headers
)

data = response.json()
```
</CodeGroup>

Replace `YOUR_ACCESS_TOKEN` with the actual token value from your session. For JavaScript integrations, always retrieve the token dynamically from the session rather than hardcoding it — tokens expire and must be refreshed.

## Token Expiry and Refresh

Access tokens are short-lived (typically **one hour**). When a token expires, all API calls return `401 Unauthorized` until you refresh it.

**Refresh the token manually:**

```javascript
const { data: { session }, error } = await xera.auth.refreshSession();

if (error) {
  // Session could not be refreshed — prompt the user to sign in again
  console.error('Session refresh failed:', error.message);
} else {
  const newAccessToken = session.access_token;
  // Use newAccessToken for subsequent API calls
}
```

**Or listen for automatic token refresh** using auth state change events — your client will receive a new session whenever the token is silently refreshed:

```javascript
xera.auth.onAuthStateChange((event, session) => {
  if (event === 'TOKEN_REFRESHED') {
    // session.access_token is now the fresh token
    updateStoredToken(session.access_token);
  }
  if (event === 'SIGNED_OUT') {
    // Clear stored token and redirect to login
    clearStoredToken();
  }
});
```

<Info>
  Xera sessions include a long-lived **refresh token** alongside the short-lived access token. The client uses the refresh token automatically to obtain a new access token in the background, so users rarely need to sign in again unless their session has been explicitly revoked.
</Info>

## Troubleshooting 401 Errors

A `401 Unauthorized` response means the server could not authenticate your request. The most common causes are:

| Cause | Fix |
|-------|-----|
| Token expired | Refresh your session and retry with the new token |
| Token missing from header | Ensure the `Authorization: Bearer <token>` header is present on every request |
| Not signed in | The user must complete the Xera sign-in flow before making API calls |
| Incorrect header format | The scheme must be exactly `Bearer ` (capital B, one space) followed by the token |
| `credentials` mode missing | For browser `fetch` calls that rely on cookies, add `credentials: 'include'` to the options |

If you continue to see `401` errors after refreshing the token, the user's session may have been revoked. In that case, redirect them to the Xera sign-in page to start a fresh session.

<Warning>
  Never expose your access token in client-side source code, public repositories, or any location visible to other users. Treat it like a password — store it only in memory or in a secure, non-public session store. If you believe your token has been compromised, sign out of Xera immediately to invalidate the session.
</Warning>
