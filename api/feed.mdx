---
title: "GET /api/app/discover/users — Retrieve the Discovery Feed"
sidebarTitle: "Discovery Feed"
description: "Fetch a ranked list of builder profiles from Xera's v2 composite recommendation algorithm, then log impressions to improve future personalization."
---

The `discover/users` endpoint returns a ranked list of builder profiles using the XERA v2 composite recommendation algorithm. The ranking blends engagement history, creator quality signals, content freshness, audience retention, and virality into a single score for each profile — so the builders that appear at the top are genuinely the most relevant to the requesting user at that moment. Feed 65% of results come from verified builders, and 35% are surfaced through organic discovery.

## Endpoint

```
GET https://xera.app/api/app/discover/users
```

## Authentication

<Note>
  This endpoint requires a valid session token passed as a Bearer token in the `Authorization` header.
</Note>

```
Authorization: Bearer <session_token>
```

## Query Parameters

<ParamField query="limit" type="number">
  Maximum number of builder profiles to return in a single response. Use this to control page size.
</ParamField>

<ParamField query="offset" type="number">
  Number of results to skip before returning the next page. Use together with `limit` for pagination.
</ParamField>

## Example Request

<CodeGroup>

```javascript JavaScript
const response = await fetch(
  "https://xera.app/api/app/discover/users?limit=20&offset=0",
  {
    method: "GET",
    headers: {
      "Authorization": "Bearer <session_token>",
    },
  }
);

const result = await response.json();
console.log(result.data.users);
```

```bash cURL
curl -G https://xera.app/api/app/discover/users \
  -H "Authorization: Bearer <session_token>" \
  --data-urlencode "limit=20" \
  --data-urlencode "offset=0"
```

</CodeGroup>

## Response Structure

<ResponseField name="success" type="boolean">
  `true` when the feed was fetched and ranked successfully.
</ResponseField>

<ResponseField name="algorithm" type="string">
  Always `"xera-v2-composite"` — identifies the ranking algorithm used to generate this response.
</ResponseField>

<ResponseField name="cached" type="boolean">
  `true` if this response was served from the recommendation cache. Cached results are used for unauthenticated or anonymous requests.
</ResponseField>

<ResponseField name="data" type="object">
  The feed payload.

  <Expandable title="data fields">
    <ResponseField name="users" type="array">
      An array of ranked builder profile objects.

      <Expandable title="user object fields">
        <ResponseField name="id" type="string (UUID)">
          The builder's unique identifier.
        </ResponseField>

        <ResponseField name="username" type="string">
          The builder's unique @handle on Xera.
        </ResponseField>

        <ResponseField name="display_name" type="string">
          The builder's public display name.
        </ResponseField>

        <ResponseField name="avatar_url" type="string">
          URL of the builder's profile avatar.
        </ResponseField>

        <ResponseField name="trajectory_score" type="number">
          A numeric score reflecting the builder's overall progression on Xera.
        </ResponseField>

        <ResponseField name="arc_count" type="number">
          Total number of ARCs (structured goals) the builder has created.
        </ResponseField>

        <ResponseField name="last_trace_at" type="string (ISO 8601)">
          Timestamp of the builder's most recent Trace (proof-of-work log entry).
        </ResponseField>

        <ResponseField name="is_verified" type="boolean">
          `true` if the builder holds a Standard, Medium, or Pro subscription plan.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

## How the Algorithm Scores Builders

The XERA v2 composite score combines five weighted signals to rank each builder profile:

| Signal | Weight | What it measures |
|--------|--------|-----------------|
| Engagement | 40% | Likes, comments, shares, and follows received |
| Creator Quality | 30% | Consistency of Traces, ARC completion rate, profile completeness |
| Freshness | 15% | How recently the builder posted a Trace or updated an ARC |
| Retention | 10% | Percentage of viewers who return to the builder's profile |
| Virality | 5% | Shares and reach beyond the builder's existing followers |

<Info>
  The feed always reserves **65% of slots for verified builders** (Standard, Medium, or Pro plan holders) and **35% for organic discovery** — ensuring a healthy mix of quality and new voices.
</Info>

## Logging Feed Impressions

### POST /api/app/feed/impression

Call this endpoint for every builder card you render in the feed. Impression data teaches the algorithm which profiles users actually see versus which ones they interact with, steadily improving the quality of future recommendations for that user.

```
POST https://xera.app/api/app/feed/impression
```

**Request Body**

<ParamField body="creator_id" type="string (UUID)" required>
  The UUID of the builder whose card was displayed.
</ParamField>

<ParamField body="impression_type" type="string">
  The context in which the card appeared. Defaults to `"regular"` if omitted.
</ParamField>

<ParamField body="position" type="number">
  The 1-based position of the card in the rendered feed list. Defaults to `1` if omitted.
</ParamField>

<ParamField body="recommendation_score" type="number">
  The composite score the algorithm assigned to this builder for this request. Pass the score back to help calibrate future rankings.
</ParamField>

<CodeGroup>

```javascript JavaScript
await fetch("https://xera.app/api/app/feed/impression", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer <session_token>",
  },
  body: JSON.stringify({
    creator_id: "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    impression_type: "regular",
    position: 1,
    recommendation_score: 87.4,
  }),
});
```

```bash cURL
curl -X POST https://xera.app/api/app/feed/impression \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <session_token>" \
  -d '{
    "creator_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "impression_type": "regular",
    "position": 1,
    "recommendation_score": 87.4
  }'
```

</CodeGroup>

<Tip>
  Fire `POST /api/app/feed/impression` for each builder card as it enters the user's viewport — not just for cards that receive a click. Impression data is most useful when it accurately reflects what the user saw, regardless of whether they interacted.
</Tip>
